# Legal retrieval review materials

This supplement supports verification of the reported legal retrieval and answer results. It accompanies the revised manuscript and supersedes the 22 and 25 November releases. `revision_20261125/` adds the pooled writer contrasts, the MBE option-phrase stratification, the breakdown of Terra's MBE gain by annotated-passage presence, the tie-order note and the values behind Table 3 and Fig. 3. `revision_20261126/` adds the analyses that answer the review: writer-versus-writer contrasts, HousingQA results without the prompt-pilot questions, paired intervals for the raw-text control, HousingQA unparseable-response rates, graph retrieval metrics under uniform tie-breaking, and the composition of the passages behind Terra's extra MBE answers. Material that the revised manuscript does not report (the HousingQA class diagnostics and the extraction assessment) and fifteen superseded MBE baseline rows in `raw_cues/aggregate_metrics.csv` are removed; the MBE baseline retrieval values are in `review_diagnostics/ir_figure_values.csv` and `statistics/candidate_recall100.csv`. Both datasets use ordinary answer accuracy. The default check runs offline on saved outcomes.

## Verify the results

Extract the entire archive to an empty directory. Open its top-level directory and, using a Python environment with NumPy, run:

```sh
python verify_bundle.py
```

The arithmetic was checked with Python 3.11 and NumPy 1.26.4. The command prints a JSON receipt with status `PASS`. It checks every data file and the verifier against the integrity manifest. The manifest itself is excluded from its own hash. Record the ZIP hash when acquiring the archive. The default command only reads files and performs deterministic arithmetic.

The verifier recomputes all 1,260 accuracy totals, 1,792 graph–baseline contrasts and both per-setting Holm adjustments. It also checks the 16 four-writer comparison rows, the 16 pooled writer contrasts and their Holm adjustment, four median absolute changes, the option-phrase strata arithmetic, the neither-found breakdown over 112 comparisons, the tie-order bounds quoted in the paper, the Table 3 and Fig. 3 values, the 12 writer-versus-writer contrasts, the HousingQA contrasts without the 384 pilot questions, the raw-text control contrasts, and the MBE reference-hit and no-retrieval breakdowns. It verifies query coverage, checksums and relationships used in scoring. The raw Monte Carlo probabilities and bootstrap intervals are from the saved runs. Optional replays redraw them: `python statistics/reproduce_statistics.py` (per-setting tests), `python revision_20261125/pooled_statistics.py` (pooled contrasts and neither-found breakdown, about 15 seconds), and `python revision_20261126/writer_pairs.py`, `housing_without_pilot.py` and `raw_text_intervals.py` in the same folder.

## Pooled contrasts, option phrases and tie order (25 November revision)

- [Pooled results](revision_20261125/final_statistics.md) ([JSON](revision_20261125/final_statistics.json)) average each writer's graph-minus-baseline accuracy difference over its 112 matched comparisons (two extractors × seven answer models × four depths × two stages). Intervals use 100,000 whole-cluster bootstrap draws and p-values use 200,000 cluster sign flips (seed 20261125; 844 MBE and 225 HousingQA clusters). Holm adjustment covers the 16 pooled contrasts. On MBE, Terra minus Qwen dense is +3.38 percentage points [2.31, 4.48].
- The option-phrase strata split Terra's MBE gain by the answer options its scored multiword phrases point to (477 / 213 / 176 / 205 questions). Only aggregates are released. Replaying the strata needs the restricted original programs and benchmark items (`pooled_statistics.py --restricted-queries PATH --benchmark PATH`); their SHA-256 fingerprints are recorded in the JSON. The verifier checks that the strata are consistent with the released option counts and with the pooled result.
- The neither-found breakdown sums Terra's net additional correct MBE answers over all 112 comparisons with Qwen dense: 3,905 of 4,059 (96.21%) come from question–setting pairs in which neither requested list contained the annotated passage. It is recomputed from [the reference transitions](review_diagnostics/mbe_requested_reference_transitions.csv).
- [Tie order](revision_20261125/corpus_order_ties.md) explains why corpus-order tie-breaking inflates MBE raw-text Hit@10 and why MBE graph ties work against the annotated passage.
- [Table 3 and Fig. 3 values](revision_20261125/paper_table3_fig3_values.csv) are recomputed from `statistics/all_fixed_stage_accuracy.csv` and `review_diagnostics/ir_figure_values.csv`.

The pooled summaries and the option-phrase stratification were added after the per-setting analysis.

## Responses to the review (26 November revision)

- [Writer pairs](revision_20261126/writer_pairs.json): pooled accuracy differences between every pair of query writers on identical graphs (112 matched settings per pair, Holm over 12 pairs). On MBE the two open-weight writers Gemma 4 and Mistral differ by +4.82 pp [3.82, 5.83]; no HousingQA pair differs significantly.
- [Without the prompt pilot](revision_20261126/housing_without_pilot.json): the eight HousingQA pooled contrasts recomputed after removing the 384 cohort questions that were also in the 500-question prompt pilot ([IDs](revision_20261126/housing_pilot_question_ids.json)). No contrast moves by more than 0.16 pp.
- [Raw-text control intervals](revision_20261126/raw_text_intervals.json): paired cluster-bootstrap intervals for raw-text search against the same writer's graph and against Qwen dense (Gemma 3 27B, initial, k = 10).
- [Unparseable responses](revision_20261126/housing_unparseable.json): HousingQA unparseable-response rates per answer model, from the total counts in the 22 November release (at most 0.5% of questions in any condition).
- [Graph ties](revision_20261126/graph_ties_results.json): MBE graph MRR@k and Hit@k under the saved identifier order, uniform random tie-breaking and the best case, from a full-corpus rescoring of both extractions that reproduces every saved top-100 list. Rescoring needs the upstream corpus and the extraction records, so only aggregates are released.
- [Passage composition](revision_20261126/passage_content_results.json): source composition of the reranked top-10 lists behind Terra's and Qwen dense's MBE answers, and how often they contain annotated passages of other or near-duplicate questions. Aggregates only; the per-question analysis uses restricted MBE item text.

## HousingQA query writers at rank one

From the supplement root, run `python housing_rq2/verify.py` for just this check. It needs only the Python standard library. The full verifier also runs it.

[The first two hits](housing_rq2/top_two.csv) give the original first- and second-ranked statute identifiers and scores for each of four query writers and each of 4,584 questions (18,336 rows). These are initial rankings on the Qwen-extracted graph, restricted to the question's jurisdiction. Each row includes its query fingerprint and the number of statutes tied at the top in the archived full-corpus replay. The checker joins the rows to the released cohort and queries, and verifies that a positive score gap agrees with a tie count of one.

At least two writers each have a unique top statute on 3,617 questions. They choose different statutes on **2,866 of all 4,584 questions (62.52%)**. On 751 questions the writers with unique winners agree, and on 967 fewer than two writers have a unique winner. Each question contributes once. Writers with a tied first place do not establish a disagreement.

[The Alabama records](housing_rq2/alabama_records.json) contain the scored fields of all 16 Qwen-extracted provisions in §35-9A-141 and all six in §35-9A-461 for HousingQA question 0. The checker reads the weighted conditions directly from the released Mistral and Terra query texts, evaluates each provision and takes the maximum within each statute. It prints the winning provision, its matched conditions and their points, and checks the scores, order and fingerprints of the winning rule texts against the saved graph results. In statute order §141 / §461, Mistral scores 80 / 70 and Terra scores 52 / 60. Both Terra provisions earn 40 phrase points and 12 legal-area points. Only the proceedings provision earns the eight-point type bonus. This local example and the cohort count use archived data and require no graph server or model calls. [Offline checker](housing_rq2/verify.py)

## Four writers and the highlighted answer comparisons

- [Writer comparisons](review_diagnostics/writer_comparisons.csv) counts higher, tied and lower ordinary accuracy for each writer against each baseline at matched stage, answer model and depth. Every row covers 112 comparisons including both extractors.
- [Answer evidence](review_diagnostics/answer_evidence.json) gives the median changes across every pair of writers and across the two extractors, the MBE answer transitions by annotated-passage presence and the MBE option-phrase counts. The MBE example is Gemma 3 27B with ten reranked passages from Terra on Qwen-extracted records or from Qwen dense.
- The MBE option-phrase counts and confirmation of complete prompt delivery come from an audit of restricted original queries and prompt records. The release includes the matching rule and aggregate results. The public verifier reproduces the answer transitions from saved correctness indicators and reference-membership flags, and checks the arithmetic of the option counts. Independently checking individual phrases or delivered prompt texts requires the restricted originals.
- [Raw-passage tie sensitivity](raw_cues/tie_sensitivity_summary.csv) includes identifier order, corpus order, expected Hit@10 under uniform tie-breaking and the two extreme tie resolutions. The raw-passage QA control selected writers using corpus order and supplied passages using identifier order.

## What the files contain

| Directory | Contents |
| --- | --- |
| `statistics/` | Correctness matrices, question IDs, cluster groups, condition definitions, accuracy and paired tests. HousingQA includes the benchmark labels. The MBE matrix contains a binary indicator of correctness for each item and configuration. |
| `queries/` | The complete text of all **18,336** HousingQA query instances. For all **4,284** MBE instances, a program structure preserves Cypher operations, schema fields, branch logic and numeric weights. Each distinct string literal within that query is replaced consistently with a placeholder. Non-schema variable names are generalised. The original full-query SHA-256 fingerprints let an authorised holder check exact identity. The masked MBE structures cannot reproduce historical rankings on their own. An executable-syntax example from the fixed MBE prompt is in `pipeline/prompts/mbe_v1.json`. |
| `revision_20261125/` | Pooled writer contrasts, option-phrase strata (aggregates), the neither-found breakdown, the tie-order note, the Table 3 and Fig. 3 values and the replay script. |
| `revision_20261126/` | Analyses answering the review: writer pairs, pilot exclusion, raw-text control intervals, unparseable rates, graph tie effects and passage composition, with replay scripts for the first three. |
| `review_diagnostics/` | Figure values, source-category counts, selected fixed-stage effect summaries, requested-reference hit strata and list lengths. All no-retrieval comparisons and hit-stratified summaries here are descriptive. The historical strata use requested passage lists. For the highlighted reranked MBE example, the prompt audit confirmed that all ten passages on each list reached the answerer. |
| `datasets/` | The two evaluated cohorts' definitions. The HousingQA mapping contains all public question IDs, question-text groups, jurisdictions, benchmark labels and corrected statute IDs for the retained cohort. Its rows link to the upstream text through the original identifiers. |
| `pipeline/` | Extraction instructions and schema source, query-generation prompts, and selected code snapshots for inspecting validation, recovery and graph construction. The scripts document the study's implementation. Rebuilding a full corpus/index requires upstream data, dependencies, model access and appropriate compute. |
| `generation_audit/` | Counts of returned responses, static validator rejections and execution recovery, plus recorded partial extraction cost. The 8.23 H100 allocation-hours cover the 66,906-passage HousingQA Llama completion only. |
| `expansion/`, `raw_cues/` | The saved raw-cue and dense-expansion control results, 225 HousingQA expansion texts and fingerprints of 1,071 MBE expansions. For MBE, `raw_cues/aggregate_metrics.csv` lists the query-writer rows only. |

Source data, licence notices and access instructions appear in [DATA_ACCESS.md](DATA_ACCESS.md). The benchmark owner provides the original exam inputs. The historical MBE search programs and expansions were generated in this study. There is currently no public access route to their withheld text. A reader who already lawfully holds an original program can compare its SHA-256 fingerprint. The fingerprint does not supply its text. Item-specific MBE answer letters, choices and original question/passage text are omitted. Full graph stores, weights and raw answer-generation outputs are also outside this compact verification package. One proprietary query generator is recorded under the alias `gpt-5.6-terra`; the historical logs do not identify a dated provider snapshot.
